Methodology & findings from grounding this in real data

Source: a real 7-prompt / 39-turn OpenSpec workflow session (create → write proposal → sync-specs → archive a change called daily-reflection-tracker), recorded by this harness with PI_CACHE_RETENTION=long set — this is the same "Cache test" recording analyzed in docs/introspect-harness/prompt-cache-reprocessing-investigation.md's "Live test results" section. Ends at 33,547 / 262,144 tokens (12.8%), comfortably inside the smart zone the whole time.

Thinking is real and substantial: usage.reasoning was 0 on every single message in this session too, but 12,864 characters of actual thinking_delta text came through — confirming design.md's finding that thinking-pill presence must key off the delta stream, not the usage field.

The cache-retention fix helped, but didn't eliminate reprocessing: summed across all 39 assistant calls, real usage.input totals 57,400 tokens against a 33,547-token final context — a 1.71× reprocessing ratio, down from 2.75× in the un-fixed recording the investigation doc started from, but still real. In this rendering, about three-quarters of every "new input" pill's mass is reprocessed context (cache miss) rather than genuinely new tool-result content — visible as input spikes right after each agent_start, same pattern as before, just smaller.

Skill auto-loads are still a distinct, sizeable category: 3 of this session's 7 top-level messages (new-change, sync-specs, archive-change) were skill files auto-injected into context rather than anything the user typed — split out here as its own pill color since it's exactly the kind of invisible context growth Apparatus exists to surface.

Rendering caveat: tool calls are drawn as small dot markers rather than stacked pills (their true token share is well under 1% of this session and would be invisible or need an unrealistic min-height otherwise). All other pill categories use real proportional height with only a 1px visibility floor.
